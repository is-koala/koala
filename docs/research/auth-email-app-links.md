## Bugünkü kopukluk

- Backend `AuthManager` kayıt e-postasını `frontendUrl + /complete-registration?token=...`, reset e-postasını `frontendUrl + /reset-password?token=...` biçiminde üretir. Güncel hedef `https://iskoala.com`; mobil ise yalnız `koala-dev`, `koala-staging`, `koala` custom scheme'lerini native olarak tanımlar. HTTPS association tanımı bulunmuyor. Kaynaklar: [AuthManager](../../../koala-backend/src/main/java/com/exskylab/koala/business/concretes/AuthManager.java), [Info.plist](../../ios/Runner/Info.plist), [AndroidManifest.xml](../../android/app/src/main/AndroidManifest.xml).
- Bu makineden `iskoala.com` A/AAAA sorguları `NOERROR` fakat boş cevap verdi; gerçek olmayan `koala-nonsecret-link-probe` değeriyle iki mail yolu da `curl` exit `6`, HTTP `000` döndü. Aynı ağda API readiness `200` döndü. **Ana domainin web içeriğine erişilemedi; bu sonuç küresel DNS arızası, 404 veya landing sayfasının kesinlikle bulunmadığı kanıtı değildir.** Yalnız mevcut erişim yolunda e-postadan HTTP sayfasına geçiş doğrulanamıyor. [Kontrol edilen kayıt yolu](https://iskoala.com/complete-registration), [reset yolu](https://iskoala.com/reset-password), [API readiness](https://api.iskoala.com/actuator/health/readiness).
- API domainindeki `/.well-known/apple-app-site-association` anonim isteği `401 application/json` döndü; bugün bu uç üzerinden public Apple association doğrulanamıyor. [Kontrol edilen uç](https://api.iskoala.com/.well-known/apple-app-site-association).
- Çalışma ağacındaki `AppLinkDestination` scheme/authority doğrulamadan `host + path` üzerinde `contains` kullanıyor. Yanlış ortam, alakasız host ve benzer isimli yol ayrılmıyor. `App` aboneliği iptal edilmiyor. Başlangıçta oturum okunmadan gelen link doğrudan router'a verilirse guard `/` yoluna gönderiyor; hedefi sonradan sürdürme mekanizması görünmüyor. Bu son durum koddan çıkarılmış yarış riski; cihazda tekrar üretilmiş sonuç değil. [Resolver](../../lib/product/router/app_link_destination.dart), [App](../../lib/product/app.dart), [router](../../lib/product/router/router_manager.dart), [splash](../../lib/employee/features/auth/presentation/pages/splash_page.dart).

## En küçük uygulanabilir QA teslimi

Bu bölüm mevcut iki kontrollü hesap ve iki simülatör için öneridir; production güvenlik kabulü değildir.

1. Mevcut `api.iskoala.com` üzerinde yalnız iki auth HTTPS landing yolu sunulsun. Normal GET yalnız açıklama ve açıkça etiketlenmiş **Koala Staging'de aç** düğmesi göstersin; token tüketmesin. Yeni frontend veya staging altyapısı gerekmez. `FRONTEND_URL` topluca değiştirilmesin: ödeme dönüşü ve aktivite bildirimleri de aynı ayarı kullanıyor. Auth dönüşü ayrı, sunucu kontrollü ayar olsun. [AuthManager](../../../koala-backend/src/main/java/com/exskylab/koala/business/concretes/AuthManager.java), [PaymentsController](../../../koala-backend/src/main/java/com/exskylab/koala/webAPI/PaymentsController.java), [ActivityNotificationManager](../../../koala-backend/src/main/java/com/exskylab/koala/business/concretes/ActivityNotificationManager.java).
2. Sunucu ayarı bu QA dağıtımında yalnız `koala-staging` üretsin; `SERVICE_ENVIRONMENT=production` etiketinden mobil flavor tahmin edilmesin. Kullanıcının verdiği serbest `redirectUrl` veya callback scheme kabul edilmesin. İleride production hedefi açıkça değiştirilsin. Landing'in üçüncü taraf script/analitik taşımaması, `no-store`/`no-referrer` kullanması ve token'ı erişim loglarına sokmayan taşımanın seçilmesi uygulama güvenlik şartları olarak test edilsin.
3. Native hedef tek biçime indirgensin: `koala-staging://complete-registration?token=...` veya `koala-staging://reset-password?token=...`. Resolver seçilmiş flavor scheme'ini, tam host'u, boş path'i ve tek/dolu token'ı doğrulasın; user-info, port, fragment, yinelenen token, başka host ve benzer yol reddedilsin. Dev/production kendi scheme'lerini kabul etsin. URL kaynaklı hiçbir değer doğrudan başarılı kayıt/reset sayılmasın; gerçek API doğrulasın. Apple da custom URL girdilerinin doğrulanmasını ve bozuk URL'lerin atılmasını ister. [Apple custom URL rehberi](https://developer.apple.com/documentation/xcode/defining-a-custom-url-scheme-for-your-app?preferredLanguage=occ).
4. Soğuk başlangıç bağlantısı oturum okuması tamamlanana kadar bellekte beklesin; ardından bir kez yönlendirilsin. Guard senkron kalmalı. Açık uygulamaya gelen link ve tekrar açılan link de test edilmeli; backend token geçerliliği son otorite olmalı. [Koala router kuralları](../../AGENTS.md#routing), [app_links 7.2.1](https://pub.dev/packages/app_links/versions/7.2.1).

Custom scheme tek uygulamaya kriptografik olarak ait değildir; başka uygulama aynı scheme'i kaydedebilir. **Landing eklemek bu riski gidermez.** Bu nedenle geçiş yalnız kontrollü QA içindir; gerçek kullanıcı lansmanında doğrulanmış HTTPS link tercih edilmeli. Apple aynı scheme'i birden fazla uygulama kaydederse seçilen uygulamanın belirsiz olduğunu açıklar. [Apple custom URL rehberi](https://developer.apple.com/documentation/xcode/defining-a-custom-url-scheme-for-your-app?preferredLanguage=occ).

## Doğrulanmış HTTPS link için eksik girdiler

iOS için Associated Domains entitlement ve public, geçerli TLS üzerinden yönlendirmesiz AASA dosyası gerekir. AASA kimliği `Application Identifier Prefix.Bundle Identifier` olmalıdır; prefix her zaman Team ID kabul edilmemelidir. Koala'nın sürüm kontrollü native dosyalarında signing Team ID/prefix veya entitlement bulunmadı; doğrulanmış imzalama girdisi alınmadan bunlar uydurulmamalı. [Apple associated domains](https://developer.apple.com/documentation/xcode/supporting-associated-domains?changes=_7_1), [Apple app identifier biçimi](https://developer.apple.com/documentation/bundleresources/applinks/details-swift.dictionary).

Android için HTTPS intent filter + `autoVerify`, public `assetlinks.json`, gerçek paket adı ve ilgili imzalama sertifikasının SHA-256 parmak izi gerekir. Play imzası yerel imzadan farklı olabilir. Ortam kimlikleri tek başına association sağlamaz; staging/production aynı cihazda kullanılırken link eşlemesi çakışmamalıdır. [Android association yapılandırması](https://developer.android.com/training/app-links/configure-assetlinks), [doğrulama ve çoklu varyant sınırı](https://developer.android.com/training/app-links/verify-applinks).

## Backend'de ayrı kabul riski: reset token tekrar kullanımı

`AuthManager.java:339–346` aynı reset JWT'sinden kullanıcıyı çıkarıp parolayı değiştirir ve oturumları kapatır; kullanılmış token kaydı kontrol etmez. `JwtService.java:53–70` reset JWT'sini kullanıcı ID + audience + zaman alanlarıyla üretir ve çıkarmada audience doğrular; token ID, tüketilme durumu veya parola sürümü bağlamaz. **Kaynak incelemesi, token süresi dolmadan tekrar kullanılabileceğine işaret ediyor; bu araştırmada canlı reset isteği yapılmadı.** Bir entegrasyon regresyon testiyle doğrulanıp ayrı backend değişikliğinde çözülmeli; yalnız mobil tekrar engeli yeterli olmaz. [AuthManager](../../../koala-backend/src/main/java/com/exskylab/koala/business/concretes/AuthManager.java), [JwtService](../../../koala-backend/src/main/java/com/exskylab/koala/core/security/JwtService.java).

Ayrıca `AuthManager.java:327` parola sıfırlamada kayıt doğrulama şablonunu seçiyor. SMTP'de reset amacına uygun başlık/gövde ve son kullanma açıklaması ayrı kabul maddesi olmalı. [AuthManager](../../../koala-backend/src/main/java/com/exskylab/koala/business/concretes/AuthManager.java).

Kabul: yanlış ortam/bozuk/eksik/tekrarlı linkler otomatik testlerde; soğuk-sıcak başlangıç iki iPhone'da; gerçek mail teslimi yalnız iki kontrollü gelen kutusunda; süresi dolmuş ve tüketilmiş token gerçek API davranışıyla doğrulanmadan paket kapanmaz.
